# 多语言

界面语言有 `en`、`zh-CN`、`ja` 三种，外加只供开发的伪语言 `en-XA`，运行中可即时切换。框架自己的界面文字都放在 UTF-8 properties 文案里，经 `com.jdesk.core.i18n.I18n` 取用；应用注册自己的文案根后用同一套 API。

## 文案文件

- **位置**：框架文案在 `jdesk-framework-frame/src/main/resources/jdesk/i18n/<命名空间>_<后缀>.properties`（如 [frame_en.properties](../../jdesk-framework-frame/src/main/resources/jdesk/i18n/frame_en.properties)）；应用的文案放在自己的资源目录，用 `I18n.registerRoot` 注册。后缀只能是 `en`、`zh_CN`、`ja`，三个文件必须齐全、键集合一致。
- **编码**：UTF-8 原文，不带 BOM，不写 `\uXXXX`，行尾 LF（框架文案由 `.gitattributes` 固定）。IDEA 里把 properties 编码设为 UTF-8，并关掉 Transparent native-to-ascii。
- **键**：写成 `<命名空间>.<区域>.<条目>`，命名空间就是文件名去掉后缀；每段只用 `[A-Za-z0-9_]`。不许重复键，也不许 `a.b` 与 `a.b.c` 并存。一个键只表达一个意思，不因某种语言里碰巧同词就复用。
- **源语言与回退**：框架文案以 `en` 为源，应用注册文案根时声明自己的源语言；取值顺序为目标语言 → `en` → 源语言 → 键名本身。伪语言由 `en` 文案变换得到。一个命名空间只归一个文案根：先注册、且有这个命名空间源语言文件的那个。
- **命名空间**：框架只有 `frame`（设置窗口、内置主题名、启动失败框、主窗口占位、状态栏、关于框、文件对话框、对话框按钮）。
- **语法**（`MessageFormatter` 实现的子集）：占位符写 `{name}`，名字以字母或下划线开头、后面跟 `[A-Za-z0-9_]`，不写 `{0}` 这类序号占位；缺参数时 `{name}` 原样留下。字面字符写 `{'x'}`，文字里不许直接出现 `{ } @ $ |`。复数只有英文能用：一个 `|` 分两段，按参数 `count` 为 1 取前段、否则取后段。不用链接消息（`@:key`）和修饰符，不嵌 HTML；局部加粗这类富文本由代码拼组件。
- **检查**：[`FrameCatalogConsistencyTest`](../../jdesk-framework-frame/src/test/java/com/jdesk/frame/i18n/FrameCatalogConsistencyTest.java) 按上面几条检查框架文案：文件名合规、三种语言齐全、键集合与 `en` 一致、每个键的占位符与 `en` 一致，不重复、不为空、没有 BOM 和转义写法、语法合法、复数只在英文里用。

## Java API

`com.jdesk.core.i18n.I18n` 是进程级静态门面，未初始化（含测试）时当前语言为 zh-CN。

| 方法 | 说明 |
| --- | --- |
| `message(key)`、`message(key, "名", 值, …)`、`message(key, Map)` | 按当前语言取文案并格式化；参数按「名, 值」成对传；找不到键返回键名本身 |
| `find(key)`、`find(key, language)`、`find(key, language, Map)` | 找不到时为空的 `Optional`。带语言的不切换当前语言，用于要同时认几种语言写法的地方 |
| `current()`、`switchTo(language)` | 当前 `UiLanguage`（`EN`、`ZH_CN`、`JA`、`PSEUDO`）；运行中切换，设 JVM 默认 locale 并发布 `LocaleListener` |
| `registerRoot(dir, loader, source)` | 注册文案根，重复注册无副作用；框架在 `JdeskApplication` 构造时注册 `jdesk/i18n`（源 `EN`），应用注册自己的根并指定源语言 |

`initialize(language)` 只在启动时由 `I18nStartup` 调用，不发布事件。⚠️ 它和 `switchTo`、启动 JVM 时传的 `-Duser.language` / `-Duser.country` 都会改 JVM 默认 locale：落库排序键、持久化格式这类要稳定的地方显式传固定 `Locale`，如打开 VFS catalog 时（见 [Managed VFS](../storage/managed-vfs.md) 的「文件名排序键与 locale」）。改过语言的测试结束时调 `I18n.resetForTests()`；框架的 Java 测试由根 pom 的 surefire 设 `jdesk.locale=zh-CN`。

### 面向用户的失败：`LocalizedException`

- `new LocalizedException(reason, params, developerMessage[, cause])`：`reason` 是文案键，`getMessage()` 是给开发者和日志看的英文，按当前语言生成提示用 `localizedMessage()`；继承来的 `getLocalizedMessage()` 仍是英文，别拿它给用户看。只在开发、协议、基础设施出错时才出现的失败直接抛英文异常，不建键。
- 桥 handler 抛出它（包括包在 `CompletionException` 里）时回 `HANDLER_FAILED`；handler 自己装失败响应时用 `WebBridgeError.of(code, failure)`。`details` 为 `{ "reason": 键, "params": {…} }`，数字与布尔参数保持原类型，其余转成字符串。桥本身见 [WebBridge 架构](../web/webbridge-architecture.md)。
- 不带 cause 的 `LocalizedException` 算按用户状态的拒绝（如文件已删），落到桥与 `ApplicationTaskScope` 的兜底处只记一行 WARN（原因码加英文说明），不打堆栈；带 cause 的与其他意外异常照旧带堆栈（`LocalizedException.rejectionOf`）。
- 框架不把界面文字交给应用：要让用户知道的状态只给原因码，由应用按码取文案，如 `HistoryStats.unavailableReason()` 给出 `HistoryUnavailableReason`，界面按它的 `code()` 翻译。框架异常消息一律英文。

### 切换话题：`LocaleListener`

- `LocaleListener.localeChanged(oldLanguage, newLanguage)` 是应用 `MessageBus` 上的话题，`I18n.switchTo` 在调用线程上同步发布，发布时拿着 `I18n` 的类锁。订阅用 `bus.connect(属主).subscribe(…)`，随属主释放，见 [消息总线](message-bus.md) 与 [资源释放](disposer.md)。
- ⚠️ Swing 订阅方自己切 EDT（`SwingUtilities.invokeLater`），回调里别 `invokeAndWait`，也别同步等别的线程，否则会和类锁互等。
- 框架里的订阅方：`SwingLocaleListener`（换 Swing 默认 locale 与字体）、`LocaleBridge`（向页面推 `locale.changed`）、打开期间的 `SettingsDialog`、`MainFrame`。
- 页面的语言通道：在 WebBridge 会话上调 `LocaleBridge.install(session)`，它注册 `locale.current` 并订阅切换、推 `locale.changed`，两者的载荷都是 `{language, cjkFallback}`，订阅随会话释放。新的 WebView 页面不装它，就拿不到 `locale.current`，也收不到切换。

## 语言设置与协商

- **设置文件**：`<home>/config/locale.properties`（`PathManager.getConfigDir()`，开发态在 `.root/<appId>/config/`），内容为 `language=<取值>`，取值为 `system`、`en`、`zh-CN`、`ja`（开发时还可以是 `en-XA`）；缺文件或值为空都按 `system`。框架里只有语言设置页写它（`LocaleSettings.write`）。文件只放一行 `language=<取值>` 加 `#` 注释行，别换写法：JVM 之外的程序（比如原生启动器）也可能读它。
- **启动**：`I18nStartup.initialize()`（`JdeskApplication` 构造时调用，见 [启动流程](application-startup-process.md)）先看 `-Djdesk.locale`，是合法语言标签就直接用；否则读设置文件，按系统语言协商。系统语言列表取 `-Djdesk.os.languages`（逗号分隔，按偏好排序），没传时取 JVM 启动时的默认 locale。
- **协商**（`LanguageNegotiator.negotiate(setting, osLanguages)`）：设置是合法语言标签时直接用它；否则按系统语言列表顺序取第一个能直接支持的（`en*` 用 en，`ja*` 用 ja，`zh` 带 `Hans` 或不带书写系统且地区不是 TW、HK、MO 时用 zh-CN）；一个都没有、但有繁体中文时用 zh-CN；其余用 en。书写系统与地区不区分大小写，`zh-Latn` 这类既不算简体也不算繁体。
- **一致性用例**：`jdesk-framework-core/src/test/resources/i18n/` 下的 [negotiation-cases.json](../../jdesk-framework-core/src/test/resources/i18n/negotiation-cases.json)（协商）、[pseudo-cases.json](../../jdesk-framework-core/src/test/resources/i18n/pseudo-cases.json)（伪语言）、[format-cases.json](../../jdesk-framework-core/src/test/resources/i18n/format-cases.json)（格式化）由 `LanguageNegotiatorTest`、`PseudoLocalizerTest`、`MessageFormatterTest` 逐条跑。其他语言的实现可以用这些用例做一致性测试；改规则必须同步改用例。
- **英文界面的汉字字形**：`LanguageNegotiator.cjkFallback` 取系统首选语言里第一个中文或日文，得 `zh` 或 `ja`，都没有时为 `zh`；ja 界面恒为 `ja`，zh-CN 恒为 `zh`。页面从 `LocaleBridge` 的载荷拿到它。
- **WebView 引擎语言**在创建时按当前界面语言设定（JCEF 后端用 `CefSettings.locale`），运行中不跟着切。

## 即时切换

设置窗口外观组（Appearance）下的语言页（`LanguageSettingsConfigurable`）先写设置文件，再 `I18n.switchTo(协商结果)`；写文件失败只记日志，本次运行照样切换。随后 Swing 换默认 locale 与界面字体，主窗口与设置窗口当场换成新语言，装了 `LocaleBridge` 的页面收到 `locale.changed`。设置窗口开着时，当前页没有未应用的修改就按新语言重建，有修改则只换标题区；分组名、设置的名称与选项、主题名要跟着语言变，注册时就传 `Supplier`（见 [frame README](../../jdesk-framework-frame/README.md)）。

已知限制：字体刷新只替换 UIResource 字体，代码里 `setFont(JdfFonts…)` 设过的字体要等组件重建；WebView 引擎语言、JVM 启动时定下的逻辑字体回退顺序要到下次启动才变；Windows 系统对话框始终跟随系统语言。

## 字体

Windows 上 Swing 按界面语言挑字体（`JdfFonts`）：

| en、en-XA | zh-CN | ja |
| --- | --- | --- |
| Segoe UI | Microsoft YaHei UI → Microsoft YaHei | Yu Gothic UI → Meiryo UI → Meiryo → MS UI Gothic |

Swing 一律经 `StyleContext` 取字体，得到带回退的复合字体。

## 伪语言

`en-XA` 由英文文案变换（`PseudoLocalizer`）：字母换成带重音的形近字，按字母数加长约四成（补 `~`），首尾加方括号；占位符与字面量原样保留，复数文案逐段变换。设置文件里是 `language=en-XA` 时界面用伪语言；Java 加 `-Djdesk.i18n.pseudo=true` 只是让语言设置页多出 `Pseudo (en-XA)` 选项。

## 中日文守卫

[`HanLiteralGuardTest`](../../jdesk-framework-frame/src/test/java/com/jdesk/frame/arch/HanLiteralGuardTest.java) 扫 `jdesk-framework-core` 与 `jdesk-framework-frame` 的 main 源码（`.java`、`.kt`），数每个文件注释以外含汉字、假名或中日文标点的行（只有全角标点的行也算）。框架界面文字一律走文案，代码里不该有写死的中日文；有意保留的登记在 [`han-literal-exceptions.txt`](../../jdesk-framework-frame/src/test/resources/arch/han-literal-exceptions.txt)，每行 `路径<TAB>计数<TAB>理由`，理由不能空（例如 `JdfFonts` 里检查字体能否显示汉字的探针字符）。文件的当前计数高于登记数时守卫失败，要把文字挪进文案；低于登记数同样失败，要手工调低这条，降到 0 就删掉。

同一个测试还扫 core、frame、demo 的 main 与 test 源码里的注释：注释一律写英文，出现中日文就失败，没有例外清单。测试代码里故意用中文的数据写在字符串里，不受影响。

## 日志

- 运行日志一律英文。文档正文、标题、搜索词与关键词、AI 提示词与对话这类用户内容不写进运行日志；路径和文件名可以记。
- 页面 `console` 由 WebView 后端转进运行日志（logger `com.jdesk.frame.webview.console`，按 console 的级别记），写 `console` 同样守上面两条；只想留 warn/error 时，在应用的 logback 配置里把这个 logger 设成 WARN。
- 守卫按整条日志调用检查（含续行，认 `LOG`、`LOGGER`、`log`、`logger`）：调用里不许有中日文，也不许出现 `title`、`body`、`content`、`query`、`keyword`、`prompt` 加 `={}` 的占位。
