Builder frame 编排

frame.launch.parallel Look & Feel 在 EDT 异步执行，应用初始化在当前 coroutine 执行。

  • application.initAsync()
  • init 完成后安装默认 ComponentStore

application.initAsync()

进入初始化态 状态检查 NOT_INITIALIZED，注册到 ApplicationManager，切换 INITIALIZING。 发布 beforeApplicationLoaded，解析插件目录，安装 frame parent-first 包规则。
core.initializeCoreServices() 注册 core 扩展点和核心服务，加载 ApplicationInfo，配置 VFS 和 LocalFileSystem。
并行解析阶段 只读取文件并构造模型，不修改 extension registry 或 service container。
plugins.load
发现插件路径，读取 bundled 注册表，并行解析 plugin.xml
frame.config.parse
读取 META-INF/frame-plugins.xml 为描述符模型
application.config.parse
读取 META-INF/app-plugins.xml 为描述符模型
三个解析任务完成后进入确定性注册
configuration.apply 按 core → frame → app 顺序注册运行时状态。
  • frame：扩展点和 frame applicationService 描述符
  • app：扩展点、内置 lazy extension、applicationService 描述符
core.initPlugins() 按依赖拓扑顺序创建插件 classloader，注册插件声明的 extension point，插件状态变为 LOADED。
core.initializeContainers() 初始化 extension registry 和 service container，预加载 AWAIT / ASYNC 服务。
INITIALIZED 发布 applicationInitialized，应用基础设施准备完成。

运行态启动

startRuntimeAsync() 要求状态为 INITIALIZED，切换 STARTING，调用 RuntimeParamRegistry.completeBoot()。
core.startPlugins() 在 Dispatchers.Default 执行，进入 PluginManager.startPlugins()。
插件贡献注册 按依赖拓扑顺序注册插件 lazy extension 和 lazy applicationService 描述符，插件状态变为 STARTED。
finishStartBeforeUiShown() 发布 beforeUiShown，切换 RUNNING，发布 onApplicationStarted。
直接 start 路径 直接路径到这里结束；builder 路径会在 finishStartBeforeUiShown() 前插入 ApplicationActivity，之后显示主窗口。

失败和回滚

异常来源 构造、初始化、frame launch、Activity 任一关键阶段抛出 RuntimeException 或 Error。
清理全局状态 initAsync() 失败会先清理 ApplicationManager。
builder 回滚 输出或写入启动 trace，调用 disposeAfterStartupFailure 释放 task scope、message bus、core 和可能已创建的 main frame。
可选退出 exitOnStartupFailure=true 时显示启动错误并使用固定退出码退出；否则重新抛出异常。

阶段说明

1. 构造阶段

JdeskApplication 构造函数准备启动所需的基础对象，但不注册全局应用，也不进入初始化态。

  • 读取 PathManager.getSystemDir()/application.properties，写入 RuntimeParamRegistry。
  • 创建 StartupTrace 和 application-owned ApplicationTaskScope。
  • 创建 ApplicationCore，内部持有 ExtensionRegistryImpl 和 ServiceContainerImpl。

2. Core 服务注册

ApplicationCore.initializeCoreServices() 是第一个运行时注册阶段，先于 frame、app 和 plugin。

  • 注册 core 扩展点 applicationService。
  • 注册 StartupTrace、ApplicationInfo、ExtensionRegistry 实例服务。
  • 注册懒加载服务 MessageBusManager 和 PluginManager。
  • 配置 VirtualFileManager，注册 LocalFileSystem 协议。

3. XML 和插件描述符解析

启动链把 frame XML、app XML 和插件描述符拆成并行解析任务。

  • FrameConfigLoader.parseFrameConfiguration() 只生成 XmlConfigurationDescriptor。
  • ApplicationConfigLoader.parseApplicationConfiguration() 只生成 XmlConfigurationDescriptor。
  • PluginManager.loadPlugins() 发现插件，并行解析 plugin.xml，记录 PluginDescriptor。

4. 确定性注册

解析结果统一在 configuration.apply 应用，避免并发任务直接修改 registry/container。

  1. core 已完成基础注册。
  2. frame 注册扩展点和 frame applicationService 描述符。
  3. app 注册扩展点、应用内置 lazy extension 和 applicationService 描述符，并保留 XML preload 策略。
  4. plugins 先注册插件声明的扩展点，再在运行态注册插件贡献。

5. 插件初始化和启动

插件生命周期被拆成 loadPlugins()、initPlugins() 和 startPlugins()。

  • loadPlugins() 只发现和解析描述符。
  • initPlugins() 创建 classloader，注册插件声明的 extension point，插件状态变为 LOADED。
  • startPlugins() 注册插件 lazy extension 和按类名创建的 service，并立即应用 preload 策略。

6. 服务容器初始化

ServiceContainer.initialize() 只预加载显式要求的服务。

  • ServicePreloadMode.AWAIT 同步创建。
  • ServicePreloadMode.ASYNC 使用应用任务域异步创建。
  • 普通服务保持懒加载，首次 getService() 时创建。

7. UI 和 Activity

builder 路径负责 frame 层 UI 阶段，所有 Swing 操作都在 EDT 执行。

  • Look & Feel 可与应用初始化并行。
  • 主题应用和 MainFrame 创建在 EDT 执行。
  • ApplicationActivity 是首窗显示前的关键活动，失败会中断启动。
  • PostStartupActivity 在首窗显示后异步投递，失败只记录日志。

8. 失败回滚

builder 路径会尽量输出启动 trace，并释放部分创建的资源。

  • 清理 ApplicationManager 的当前应用引用。
  • 取消应用任务域，释放 message bus、core、service container 和 extension registry。
  • 如果 main frame 已创建，也会在失败清理中释放。
